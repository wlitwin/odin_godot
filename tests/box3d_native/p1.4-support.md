# P1.4 native crash and normalization support

Coordinator t12 assigned this follow-up after P1.3 closure, expanded the P1.4
native patch/test scope, and explicitly authorized
`box3d/native/patches/broadphase_rebuild.patch`. No new card was claimed and the
coordinator's benchmark sources were not edited. All reproductions use the
worker's own scratch directory.

The original retained Debug executable reproduced its SIGTRAP under LLDB with
arguments `500 1 2400 128 30 OUTPUT`. The matching macOS DiagnosticReport and
live debugger agree on the failure:

```text
b3InternalAssert: ( node->flags & b3_enlargedNode ) == 0
b3DynamicTree_ValidateNoEnlarged (dynamic_tree.c:1078)
b3ValidateNoEnlarged (broad_phase.c:530)
b3Solve (solver.c:2083)
b3World_Step
ogb3_world_step -> ogb3_world_step_fixed
box3d.world_step_fixed -> main.advance -> main.main
```

The failing world is the independent baseline: packed world 1, native worldId 0,
stepIndex 1760, sparse bodies 503. Dynamic-tree node 164 is the root, flags 3
(`allocated | enlarged`), node capacity 1167. A debugger stop before that step's
pair update finds stepIndex 1759 and `moveArray.count == 0`, while that root is
still marked enlarged. Tick 1760 is the deterministic extra-sphere destruction
boundary. A scratch copy of the current fixture with only a forward baseline
loop reproduces under both final two-patch Debug and Release, without any dump,
capture or restore operations. This rules out snapshot publication as the
trigger for this assertion.

The minimal reproduction needs three bodies: zero gravity, create three boxes,
step, move a leaf whose parent is not the root, step, then destroy that body.
Before destruction the only pending move is that proxy. Destruction removes it
from the move queue while ancestors still need rebuilding. The old
`b3UpdateBroadPhasePairs` returns immediately when the queue is empty, skipping
its normal tree-maintenance task. The solver then asserts. The reproduced
pre-step state is:

```text
after_move buffered=1 root_flags=3
after_destroy buffered=0 root_flags=3 nodes=3
```

The correction calls the existing `b3UpdateTreesTask(world)` synchronously in
that empty-move branch before returning. It rebuilds dynamic and kinematic trees, clearing enlarged state through normal
tree maintenance without fabricating pairs or disabling any assertion. The normal path still queries pairs before scheduling its potentially
parallel tree rebuild; moving maintenance ahead of those queries would introduce
a race and is deliberately avoided. Public-operation regressions cover both
dynamic and kinematic bodies. The same minimal reproducer passes after the fix;
the 500-body seed 1 forward baseline completes all 2,400 ticks after the patch.

The native build owner independently verified application/result bytes and
integrated this third patch after the two previously approved alignment patches.
Fetched/pristine sources and other workers' scratch trees were not modified.

An independent native review also found an inactive-state normalization error:
compound and multi-material shapes do not initialize their inline `material`
field because `materials` supplies their active array. The old generated shape
base emitter included that inactive inline value, and then emitted active
materials separately. Dump v2 removes the inline field from the base emitter;
the existing active-material traversal supplies either inline or array data
exactly once. The changed stream is explicitly version 2 and coverage
`ogb3-d421e45c-solver-v2`; v1 evidence remains historical. Tests change inactive
compound inline friction/restitution without affecting the digest, and change
active array friction with an expected digest change. Odin constants and the
strict benchmark parser are coordinated by the binding/coordinator workers.

A further boundary review found the first uncached fingerprint probe needs a
native world slot. The native API owner now prewarms it before public world
creation and returns 0 when a foreign/full native domain cannot be safely
initialized/probed. Snapshot capture/validation treat 0 as `Capacity` and never
store it as a compatibility token. This worker's initial-process regression
creates 128 bare native worlds before public initialization, checks first-call
fingerprint 0/capture `Capacity` with unchanged allocations, destroys them, and
then runs normal public lifecycle tests. The API owner's smoke separately tests
128 public worlds, failed restore at capacity preserving destination gravity and
allocation state, and successful restore after freeing a slot. Existing host
callback use retains an explicit nonreentry requirement; the flat API exposes no
callback setter.

After these changes, the worker's Debug CTest and full AddressSanitizer plus
UndefinedBehaviorSanitizer CTest each pass 3/3, with alignment checking enabled
and no suppressions. Native lifecycle teardown reports zero engine and owned
wrapper live bytes. Native source/header/tests were frozen after these checks
for the build owner's coherent macOS/Linux reruns. Current repository Odin
lifecycle and final forward-baseline results, source hashes and raw log paths
are recorded in [p1.4-support.json](p1.4-support.json). Odin v2 passes 5/5, the
final forward baseline passes 2,400 ticks, and macOS leaks reports zero leaks.

The root coordinator must rerun the full corrected benchmark corpus, including

forward baseline regression proves this assertion is fixed for the reproduced
