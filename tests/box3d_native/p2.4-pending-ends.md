# P2.4 pending end-queue support, normalized v3

Coordinator t12 assigned this integration correction after the independent
public-operation `tests/box3d_framework/pending_end_probe.c` found
`baseline=1 restored=0`. No new card was claimed, no agents were started, and
benchmark files were not edited. Historical Gate A/P1/P2.1 v2 reports, manifests,
archives and timing evidence remain historical and were not rewritten as v3.

The old restore incorrectly treated both end-event buffers as completed outputs.
At a settled boundary, `endEventArrayIndex` identifies a future delivery queue:
post-step body/shape destruction appends ends there. The next fixed step keeps
those entries, adds its own ends, flips buffers, exposes the old current queue,
and clears the new current queue. The opposite buffer is completed output.
The pinned upstream image stores the index but omits both buffers' contents.

Owned resource contract version 2 now copies current pending sensor/contact end
queues as immutable ordered local allocation keys. Restore imports them into
the disposable candidate before publication, reconstructing shape IDs with their
16-bit generations and contact IDs with full 32-bit generations for the final
destination world. Both end arrays move with simulation storage; the candidate's
completed opposite buffer is empty. Other completed native outputs and body-move
linkage still clear. Pending entries are delivered on the next step exactly once.
Clone, detached source lifetime and restored-world geometry/resource leases retain
the supplement safely. The queue has an explicit 65,536-entry bound per family;
excess rejects with Capacity, without truncation or mutation.

The supplements are part of wrapper allocation/storage accounting and the
resource integrity seal. They are independent copies, not borrowed native array
pointers. Allocation failure cleans all partial image/cache/queue resources.
Pending arrays are populated before the post-import rejection point, so failure
cleanup exercises valid candidate destruction including those arrays. There is
no corrupt destructive-loader recovery claim and no new upstream engine patch.

Normalized version 3, coverage `ogb3-d421e45c-solver-v3`, retains the prior typed
logical coverage and appends these fields after the constraint graph:

```text
sensor_pending_count: nonnegative i32
  sensor_shape_key: u64; visitor_shape_key: u64   (ordered entries)
contact_pending_count: nonnegative i32
  shape_a_key: u64; shape_b_key: u64; contact_key: u64 (ordered entries)
```

A key is index1 in low 32 and generation in high 32. Shape generations use 16 bits;
contact generations use all 32. World slots and contact padding are excluded.
Count, order and generation affect equality even with identical current poses.
Completed buffers remain excluded; Replay's provider separately preserves copied
completed-step sensor observations for same-tick action/read rollback. Native
pending state then flows automatically through its next fixed step. Kit's
post-step settle mutation uses the same future-queue contract.

The Odin/native handshake now checks actual native `state_version()` against
compiled `STATE_DUMP_VERSION`, in addition to ABI/layout checks. World/stage
creation, snapshot operations and world/detached admission reject a mismatched
ABI-compatible v2 archive with Incompatible before provider/world use. Cleanup
and version diagnostics remain available. The resource version is an opaque
native tag checked per snapshot, with no public runtime version getter.
`tests/box3d/version_mismatch` was linked to a retained coherent v2 archive and
reported native 2/compiled 3, Incompatible before world use, zero native and wrapper
allocations. Historical artifact inspection is separate from current acceptance.
