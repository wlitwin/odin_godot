## Required flow evidence

| Flow | Required observable result |
| --- | --- |
| Late join | Authority progresses before real enrollment; a complete current Welcome is adopted; all five parts match; valid future controls and eligible effects continue. |
| Spectator | Real spectator enrollment and complete state, no input/action or predicted work, continued authoritative complete-state equality and no spurious effects. |
| Reconnect | Actual departure and replacement connection; retained logical identity binds a new peer/generation/bootstrap scope; old-context traffic cannot mutate or steer the replacement. |
| Canonical hard resync | Actual public request or history-loss mechanism; last complete publication survives partial/corrupt/stale candidates; a complete valid replacement restores future operation and checked ownership. |

Use each framework's existing Session, admission and recovery mechanism. The
shared Native backend owns solver images and immutable assets; it does not own
network enrollment or create a second timeline. A send call is not receipt or
publication evidence. Check the receiver's actual adopted scope, complete state,
frontiers, effects, resource owners and valid future work.

Candidate corruption is explicit test input. It must not be confused with
assigning a successful head, generation, confirmation, readiness or recovery
counter. Partial/duplicate/conflicting/stale transfers require bounded resources
and a valid follow-up transfer. Rejected work cannot emit confirmed effects or
silently retarget an already attempted logical action.

## Kit contract

Session spectator enrollment is distinct from World simulation policy. A
receive-only World consumer uses zero-delta ingress and verified accepted-input/
signature catchup, or a real Reset when the retained window is insufficient.
There is no claim that a spectator flag alone blocks a generic positive World
frame. The fixture must prove its no-input/no-prediction policy.

Same-token reconnect requires a real Session departure and a new peer binding.
Forward actual disconnection to the World protocol feedback/scope boundary.
Welcome/Reset sequences are generated by the real producer; they are adopted
only after complete verified publication. Existing example terminal signature
ACKs belong to its application lane, not an invented World ACK protocol.

Adding a fresh logical driver after the legacy example has started is explicitly
unsupported by that example contract. It is different from replacing the peer
for an existing identity, or enrolling a receive-only spectator.

## Replay contract

Authority construction uses complete checkpoints. Clients and observers use the
ordinary public session constructor and receive a complete Welcome; the authority
constructor is not a Client/Observer seeding shortcut. A spectator cannot call
the driver step/action path. Actual signed facts and canonical snapshots can
advance its authoritative state without creating predicted input.

`client_reconnect` preserves complete Timeline state while resetting transient
network assembly state. A replacement needs a new connection or actual timeout;
retrying Hello on an already-running incarnation does not create a new identity.
Memory transport time advances are bounded to10000 per call, and test schedules
must check that they actually occurred.

Hard resync follows actual missing history and the existing public pump/request/
Welcome flow. Same-scope signed-fact healing is a separate outcome. There is no
public manual Replay UI Reset in the current sample; private resync functions
are not a substitute. Complete authority handoff uses its separate complete-state
departure/seed APIs and must not inherit a value-only recovery claim.
