# odin_godot documentation website

The SDK home page, task-based documentation, API notes, examples, and illustrated
multiplayer guide. The site uses a shared `o/g` header, documentation sidebar,
on-page navigation, and keyboard-accessible search.

Open the [home page](dist/index.html), or serve it from this repository root:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/visual-guide/dist
```

Visit <http://127.0.0.1:8765>. There is no installation or build step. Serving over
HTTP enables documentation search and legacy reference redirects. Use Print /
save PDF on an article for a paper copy.

The main entry points are [SDK docs](dist/docs.html), [examples](dist/examples.html),
the [multiplayer field guide](dist/guide.html), and the
[documentation index](dist/reading.html). The index lists every published page
by topic, with no collapsed sections. It is generated from the same inventory as
the articles; the site checker verifies that each source appears exactly once.
Existing article URLs remain valid.

The [desk reference](dist/field-guide.md), [print edition](dist/field-guide.pdf),
and six [SVG diagrams](dist/diagrams) are standalone artifacts. `dist/` is the
complete portable website. The PDF captures the article in its initial state;
the website retains the interactive controls.

The home page is generated by `build-product.mjs`. `site-structure.mjs` defines
routes and documentation navigation. `dist/sdk.css` and `dist/site.js` supply the
shared layout and search. The visual field guide remains authored in
`dist/guide.html`; `dist/app.js` drives its interactive models.

Editorial changes follow the [documentation style guide](EDITORIAL.md), written
for developers who know programming and game development but are new to this SDK.

Task-based tutorials live in `content/`. `build-readers.mjs` renders them and the
repository's linked documents into HTML, with highlighted code, tables, and
static diagrams. Related Markdown links resolve to other reading pages. Original
source files remain available as downloads.

Viewing the site needs no dependencies. To regenerate the reading pages, SVGs,
and source snapshots after API changes, install the pinned build dependencies once:

```sh
cd docs/visual-guide
npm ci
```

Then, from the repository root:

```sh
node docs/visual-guide/prepare.mjs
```

`build-readers.mjs` follows links from the guide's selected references and generates
the documentation pages. `build-index.mjs` groups the complete page inventory
into the browsable index. New Mermaid diagrams are rendered to static SVG
using Chrome; set `GUIDE_CHROME` if Chrome is installed at a nonstandard path.
Cached SVGs do not require a browser. Newly rendered diagrams are serialized as
XML and decoded as images before publication. The link checker also rejects
malformed SVGs and unresolved escape tokens. No Markdown parser or diagram
runtime ships to visitors.

The generator reads repository files, records their Git baseline in
`dist/reference-manifest.json`, and refreshes the bundled copies. It does not
change the original docs, frameworks, or game examples. The browser correction
model is deliberately smaller than the Odin Loot model; it is not a runtime port.

The hosting manifest in `.openai/hosting.json` identifies the private Sites
publication. The website needs no connected apps, credentials, or backend.

## Publish from the SDK repository with GitHub Pages

Keep this guide in `odin_godot`. GitHub calls this a **project site**, with the
default address <https://wlitwin.github.io/odin_godot/>. A user site at
`wlitwin.github.io` would instead need a repository named `wlitwin.github.io`.
The project site keeps documentation changes with the SDK versions they describe.

The [Documentation workflow](../../.github/workflows/pages.yml) installs the pinned
documentation tools, regenerates the guide and reading pages, checks local links
and section anchors, and publishes only `docs/visual-guide/dist`. Pull requests
build and check the site; pushes to `main` deploy it independently of the game tests.
No GitHub token or hosting secret needs to be added.

One-time setup after committing and pushing these files:

1. Open [Settings → Pages](https://github.com/wlitwin/odin_godot/settings/pages).
2. Under **Build and deployment**, choose **GitHub Actions** as the source.
3. Run **Documentation** from the Actions tab, or push the next change to `main`.
4. After the deployment succeeds, use `https://wlitwin.github.io/odin_godot/` for
   the repository's website field and documentation link.

All assets, reading links, and JavaScript fetches use relative paths, so the same
output works at a project subpath, a user-site root, or a custom domain. The Pages
artifact is the contents of `dist`, with its `index.html` at the artifact root;
it does not need Jekyll or a `gh-pages` branch.

Check an updated build locally with:

```sh
node docs/visual-guide/prepare.mjs
python3 docs/visual-guide/check-site.py
```

GitHub's instructions: [project and user sites](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
and [publishing through Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Scrapyard showcase

The home page links to the [live Scrapyard browser build](https://itchyitches.itch.io/scrapyard)
and uses a screenshot captured from that build. It also links to the repository's
Replay Scrapyard contributor and code guides. The live build and the Replay port
have separate implementation histories; the showcase does not assign a framework
or parity claim to an unversioned itch.io upload.
